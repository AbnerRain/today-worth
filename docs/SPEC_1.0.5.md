# 《摸力全开》v1.0.5 产品与技术规格

版本：v1.0.5

文档状态：开发完成，待体验版验证

创建日期：2026-08-13

基线版本：v1.0.4

产品实现基准：`miniprogram/`

## 1. 背景

v1.0.4 已完成工资换算、首次引导、带薪活动计时、自定义活动、钞票金币雨、活动结算、日周月生涯统计、18 枚成就和微信好友分享，并已正式上线。

当前阶段不需要继续扩张社交和游戏化功能。v1.0.5 的任务是让现有主流程更稳定、可纠错、可分析，为后续推广和 v1.1.0 的复访功能提供可靠数据。

## 2. 版本目标

v1.0.5 需要解决四类问题：

1. 识别用户来源，观察首次使用和分享转化。
2. 允许用户撤销或删除错误记录。
3. 小程序进入后台或进程被回收后能够恢复计时。
4. 分享卡在常规和极端金额下都不发生文字溢出。

## 3. 成功标准

### 3.1 产品目标

- 推广渠道可区分，核心行为可形成完整漏斗。
- 计时被打断后能够继续，不产生负时长、重复记录或重复计时器。
- 用户可以纠正单次误记录，不需要清空全部数据。
- 四种活动的分享卡金额均完整、清晰且保持原有视觉风格。

### 3.2 上线观察指标

以下为首阶段内部目标，不代表行业基准：

- 首次工资设置完成率不低于 60%。
- 首次计时启动率不低于 50%。
- 已启动用户的计时完成率不低于 70%。
- 结算页分享面板打开率不低于 8%。
- 次日回访率不低于 15%。
- 规定测试场景中的计时恢复成功率为 100%。
- 严重错误、数据丢失投诉为 0。

## 4. 版本范围

### 4.1 本版包含

- 渠道参数识别。
- 微信自定义分析事件上报。
- 活动计时状态持久化与恢复。
- 超长计时确认。
- 结算页撤销本次记录。
- 收益明细查看与单条删除。
- 历史记录数据结构升级和兼容。
- 分享金额按实际宽度自适应。
- 自动化测试、压力测试和真机测试扩充。

### 4.2 本版不包含

- 好友关系和排行榜。
- 微信登录、手机号登录或其他账号体系。
- 云端保存工资和计时明细。
- 手动修改历史金额和时长。
- 手动补录历史记录。
- 多个自定义活动。
- 每周总结卡。
- 连续签到和签到奖励。
- 分享解锁、邀请助力或积分商城。
- 广告接入。

## 5. 核心用户流程

### 5.1 推广进入

1. 用户通过带渠道参数的小程序码或分享卡进入首页。
2. 系统读取入口 `scene`、页面路径和 `src` 参数。
3. 系统规范化渠道编号，非法值统一归入 `unknown`。
4. 首次用户进入工资设置引导，老用户直接进入首页。
5. 后续关键事件携带本次入口渠道和当前版本号。

### 5.2 开始与恢复计时

1. 用户选择活动并点击开始。
2. 系统保存开始时间、活动类型和开始时的秒薪快照。
3. 页面按真实时间差显示计时与收益。
4. 小程序进入后台、被系统回收或重新打开时，从本机恢复活动计时。
5. 用户结束后生成一条记录，并清除活动计时缓存。

### 5.3 撤销与删除

1. 计时结束后，结算页提供弱化的“撤销本次记录”入口。
2. 用户确认后，系统只删除本次记录并重新计算首页、统计、愿望单和成就。
3. 用户也可在统计页点击收益明细，查看记录详情并删除指定记录。
4. 删除操作必须二次确认，取消后不改变任何数据。

### 5.4 分享

1. 结算页生成对应活动的动态分享卡。
2. 分享卡保留原图、标题、活动颜色和“本次入账”等原有元素。
3. 金额根据可用宽度自动调整字号。
4. 金额仍过长时，仅分享卡采用“万”或“亿”的紧凑格式；分享标题保留完整格式化金额。
5. 动态图片生成失败时，使用现有结算页面截图或静态活动卡降级。

## 6. 功能需求与验收

### FR-101 渠道参数识别

渠道参数使用 `src`，首批固定值如下：

| 渠道 | `src` |
| --- | --- |
| 微信好友 | `wechat_friend` |
| 微信群 | `wechat_group` |
| 朋友圈 | `moments` |
| 小红书 | `xiaohongshu` |
| 视频号 | `video_account` |
| 公众号 | `official_account` |
| 微信搜索或无参数入口 | `organic` |
| 未识别参数 | `unknown` |

验收标准：

- 冷启动和热启动都能读取当前入口参数。
- 无 `src` 时使用 `organic`。
- 只接受白名单渠道值，不保存任意外部字符串。
- 分享卡入口继续支持区分普通分享与统计分享。
- 渠道解析失败不得阻止首页加载。

### FR-102 自定义分析事件

使用微信自定义分析上报以下事件：

| 事件名 | 触发时机 | 字段 |
| --- | --- | --- |
| `onboarding_view` | 首次引导展示 | `channel`、`version` |
| `onboarding_complete` | 首次工资设置保存成功 | `channel`、`version` |
| `timer_start` | 活动计时成功开始 | `channel`、`activity`、`version` |
| `timer_complete` | 活动记录成功写入 | `activity`、`duration_bucket`、`money_bucket`、`version` |
| `timer_restore` | 从本机恢复活动计时 | `activity`、`duration_bucket`、`version` |
| `timer_cancel` | 用户撤销本次记录 | `activity`、`version` |
| `report_share_open` | 用户调起分享面板 | `activity`、`money_bucket`、`version` |
| `stats_view` | 统计页展示 | `period`、`version` |
| `achievement_view` | 成就页展示 | `unlock_bucket`、`version` |
| `record_delete` | 用户删除历史记录 | `activity`、`version` |

区间字段使用固定枚举，禁止发送精确值：

- `duration_bucket`：`lt_1m`、`1m_5m`、`5m_15m`、`15m_30m`、`30m_1h`、`gte_1h`。
- `money_bucket`：`lt_1`、`1_5`、`5_20`、`20_50`、`50_100`、`gte_100`。
- `unlock_bucket`：`0`、`1_5`、`6_12`、`13_17`、`18`。

验收标准：

- 后台未配置事件或当前基础库不支持接口时，业务流程不报错。
- 同一次用户操作只上报一次。
- 调起分享面板只记录为 `report_share_open`，不得命名为“分享成功”。
- 上报数据不包含月薪、精确金额、精确时长、用户代号和自定义活动名称。

### FR-201 计时状态持久化

活动计时缓存键：

```text
moli-active-timer-v1
```

数据结构：

```json
{
  "id": "timer_1720000000000_xxxx",
  "activity": "toilet",
  "startedAt": 1720000000000,
  "secondRate": 0.018939,
  "schemaVersion": 1
}
```

验收标准：

- 点击开始成功后再写入缓存，写入失败时提示用户且不进入虚假计时状态。
- 恢复时以 `startedAt` 和当前时间计算经过时长。
- 恢复后使用 `secondRate` 快照，不受后续工资设置变化影响。
- 正常结束、撤销或放弃后清除缓存。
- 连续点击开始不得创建多个计时器。
- 本机存在损坏缓存时自动清除，并回到未开始状态。
- 当前时间早于 `startedAt` 时不得产生负时长。

### FR-202 超长计时确认

计时超过 12 小时后，用户点击结束时弹出确认：

> 本次记录持续时间较长，是否按完整时长结算？

操作：

- “按完整时长结算”：生成正常记录。
- “放弃本次记录”：清除活动缓存，不生成记录。
- 关闭弹窗：继续保持计时状态。

验收标准：

- 不自动截断时长。
- 不自动删除活动。
- 弹窗重复打开不会重复生成记录。

### FR-301 记录数据结构升级

新记录结构：

```json
{
  "id": "session_1720000900000_xxxx",
  "activity": "meal",
  "startedAt": 1720000000000,
  "endedAt": 1720000900000,
  "seconds": 900,
  "money": 17.05,
  "rateSnapshot": 0.018944,
  "source": "timer",
  "schemaVersion": 2
}
```

验收标准：

- 新记录必须具有唯一且稳定的 `id`。
- 旧记录读取时补齐兼容字段，不修改其原始时长和金额。
- 数据迁移可重复执行，不能重复生成多份记录。
- 继续保留最近 5000 条记录的本机上限。
- 统计和成就同时兼容新旧记录。

### FR-302 结算页撤销

交互要求：

- 在现有分享按钮和关闭按钮下方增加弱化文字操作“记录有误？撤销本次”。
- 点击后弹出二次确认。
- 撤销成功后关闭结算页，并刷新首页、统计、愿望单和成就数据。

验收标准：

- 只删除当前结算对应的记录。
- 重复点击不会误删其他记录。
- 当前记录已不存在时提示“记录已撤销”，不报错。
- 撤销后相关累计数据立即减少。

### FR-303 收益明细详情与删除

交互要求：

- 统计页收益明细行可点击。
- 点击后打开记录详情弹层。
- 展示活动、日期、开始时间、结束时间、时长和入账金额。
- 底部提供“删除此记录”，删除前二次确认。

验收标准：

- 删除后保持当前统计周期不变。
- 删除后统计汇总、活动贡献、愿望单和成就同步更新。
- 取消删除不改变数据。
- 空记录状态继续使用现有随机文案。

### FR-401 分享金额自适应

绘制规则：

- 金额区域宽度沿用现有分享卡设计。
- 默认字号为 27px，最小字号为 14px。
- 使用 `measureText()` 获取真实文本宽度，逐级缩小直至进入安全宽度。
- 金额左右至少保留 6px 安全距离。
- 超出最小字号承载能力时，使用最多两位小数的“万”或“亿”紧凑格式。
- 四种活动继续使用各自主题色和相同粗体风格。

必须验证的金额：

```text
￥0.00
￥0.01
￥999.99
￥9999.99
￥99999.99
￥999999.99
￥9999999.99
￥999999999.99
```

验收标准：

- 金额不超出白色金额区域。
- “本次入账”和“按秒结算”保持完整可见。
- 不改变分享卡的其他图片、文字和布局。
- 拉屎、吃饭、睡觉和自定义分享卡分别验证。

## 7. 数据迁移与兼容

### 7.1 迁移原则

- 不清空 v1.0.4 用户数据。
- 不因迁移重新计算旧记录金额。
- 迁移失败时保留原始数据，并继续以兼容模式读取。
- 迁移过程只在本机执行，不上传记录。

### 7.2 老记录兼容

老记录缺失 `id`、`startedAt`、`endedAt`、`rateSnapshot` 时：

- 使用原 `at` 作为 `endedAt`。
- 使用 `seconds` 推算 `startedAt`。
- `rateSnapshot` 可由 `money / seconds` 推算，无法推算时为 `null`。
- 生成稳定兼容 ID，不能依赖数组实时下标。

### 7.3 回滚兼容

- v1.0.5 新增字段不能破坏 v1.0.4 所需的 `activity`、`seconds`、`money` 和 `at`。
- 如需回滚至 v1.0.4，旧版本仍能读取核心统计字段。

## 8. 隐私与安全

- 工资配置、精确计时记录和精确金额继续只保存在本机。
- 自定义分析仅上报匿名行为事件和区间枚举。
- 不接入微信登录、手机号、位置、通讯录或设备标识。
- 不在客户端保存 AppSecret 或任何服务端密钥。
- 非法渠道参数必须白名单化，不直接作为界面内容或分析字段。
- 设置页和首次引导中的隐私文案应准确说明匿名使用分析的范围。
- 清空本机数据时同时清除活动计时缓存、渠道缓存和迁移状态。

## 9. UI 与交互约束

- 延续年轻职场漫画风，不重做首页结构和底部导航。
- 新增操作不能挤压当前开始按钮、活动模式和分享按钮。
- 删除与撤销属于危险操作，颜色可使用提醒红，但不能成为页面主视觉。
- 详情弹层必须支持明确关闭和取消。
- 所有主要触控区域不低于 44px。
- 320px 至 430px 宽度下不得出现横向滚动。
- 系统大字号下按钮文字不能裁切或偏心。
- 动画与钞票雨不因计时恢复而重复叠加多个实例。

## 10. 异常与降级策略

| 异常 | 处理方式 |
| --- | --- |
| 自定义分析接口不存在 | 跳过上报，业务继续 |
| 分析事件后台未配置 | 捕获失败，业务继续 |
| 活动缓存损坏 | 清除缓存并提示重新开始 |
| 本机存储写入失败 | 不开始计时，提示稍后重试 |
| 系统时间回拨 | 按 0 秒保护，不生成负时长 |
| 重复结束计时 | 只允许第一笔成功写入 |
| 待撤销记录已删除 | 提示已撤销，不删除其他记录 |
| 分享 Canvas 生成失败 | 使用现有截图或静态分享卡 |
| 金额非有限数值 | 按 `￥0.00` 降级，记录异常日志 |

## 11. 测试规格

### 11.1 自动化测试

数据层：

- 新旧记录迁移。
- 稳定 ID 和重复迁移。
- 单条删除与撤销。
- 删除后汇总、愿望单和成就重算。
- 5000 条记录上限。
- 损坏数据降级。

计时层：

- 后台 5 分钟后恢复。
- 进程关闭后重新打开恢复。
- 跨零点计时。
- 修改工资后仍使用原秒薪。
- 连续点击开始只生成一个活动缓存。
- 超过 12 小时触发确认。
- 时间回拨不产生负数。

分享层：

- 四种活动金额和颜色正确。
- 八组边界金额完整显示。
- 动态图失败后正常降级。
- 分享标题保留完整金额。
- 分享图保持 500 × 400 和 5:4 比例。

分析层：

- 渠道白名单和默认渠道。
- 冷启动、热启动参数更新。
- 不支持分析接口时不崩溃。
- 区间字段边界正确。
- 上报内容不包含敏感字段。

### 11.2 真机测试矩阵

- iPhone SE 类小屏。
- iPhone 12/13 标准尺寸。
- iPhone Pro Max 大屏。
- 安卓窄屏和安卓大屏。
- 系统大字号。
- 深色模式。
- 弱网、断网和无网络。
- 微信前后台切换。
- 微信进程结束后恢复。

### 11.3 压力测试

- 5000 条本地记录聚合和删除。
- 100 万次金额格式化与绘制。
- 2 万次分享卡生成模拟。
- 1000 次分析事件调用。
- 100 次开始、结束、撤销循环。

### 11.4 发布门禁

- `npm run test:release` 全部通过。
- `git diff --check` 通过。
- 主包保持低于微信限制，并记录实际大小。
- 微信开发者工具代码质量检查无阻断项。
- 四种活动在真机完成开始、恢复、结束、撤销和分享闭环。
- Git 工作区只包含本版本相关文件。

建议按以下顺序实施，每一项独立提交：

1. `refactor: 升级计时记录数据结构`

3. `feat: 支持撤销和删除单条记录`

1. 所有开发在 `develop` 分支完成。
2. 完成自动化测试、压力测试和多尺寸检查。
3. 上传 v1.0.5 微信体验版。
4. 邀请 5 至 10 名真实用户测试两天。
5. 验证计时恢复、撤销删除、分享卡和分析事件。
6. 检查微信后台是否正常接收自定义分析。
7. 修复阻断问题后提交审核。
8. 审核通过后发布，并观察 7 至 14 天。
9. 根据实际漏斗和反馈决定 v1.1.0 范围。

## 15. v1.1.0 候选范围

v1.1.0 只在 v1.0.5 上线观察后启动，候选内容如下：

### 15.1 每周摸鱼工资条

- 本周次数、时长和收入。
- 收入最高的活动。
- 与上周对比。
- 本周新增成就。
- 随机职场评语。
- 专属 5:4 分享卡。

### 15.2 连续记录

- 连续有记录天数。
- 本周已完成活动数。
- 不设置签到奖励，不弹窗催促。

### 15.3 多个自定义活动

- 最多保存 3 个自定义活动。
- 支持修改、排序和删除。
- 每个活动独立统计。

### 15.4 数据备份与恢复
