# 《时间工资条》产品规格说明

版本：v0.1  
更新时间：2026-07-28  
当前阶段：H5 Demo 验证，后续迁移为微信小程序

## 1. 产品定位

《时间工资条》是一个面向打工人的轻量时间价值小程序。它把工作日里的时间片段换算成金额，用“荒诞但克制”的方式让用户看见自己的时间价值。

核心不是严肃记账，也不是纯搞笑工具，而是一个带分享属性的个人时间价值仪表盘。

## 2. 目标用户

- 有固定月薪或较稳定收入的上班族。
- 对“带薪时间”“摸鱼成本”“会议浪费”这类话题有共鸣的人。
- 愿意把轻量战报分享给朋友，形成互动和调侃的人。

## 3. 核心价值

- 让抽象时间变成具体金额。
- 让无聊、通勤、会议、加班等场景变成可记录的趣味账本。
- 通过战报和成就增强分享和回访。

## 4. 产品边界

### 要做

- 计算时薪、每分钟价值、每秒价值。
- 选择“带薪拉屎”“带薪吃饭”或“带薪睡觉”，记录一次带薪活动并生成对应战报。
- 记录通勤、咖啡、会议、加班等时间价值场景。
- 展示日、周、月、职业生涯统计。
- 展示成就系统的雏形。
- 支持分享战报和复制分享文案。

### 暂不做

- 不做严肃财务管理。
- 不做复杂工时排班系统。
- 不做真实工资联网校验。
- 不做过重的社区广场。
- 当前版本不做排行、好友关系和分享回流。
- 不做带攻击性的公司、老板、同事标签。

## 5. 信息架构

底部 Tab 固定为三个一级入口：

- 首页：计时、实时收益、快捷账本、今日累计。
- 统计：日、周、月、职业生涯的数据概览和时间轨迹。
- 成就：个人成就、锁定状态、解锁反馈。

设置入口固定在首页顶部右侧，用于维护工资换算参数。

## 6. 核心流程

### 6.1 初次打开

1. 用户进入首页。
2. 默认展示月薪 12000、每月 22 个工作日、每天 8 小时。
3. 用户可进入工资设置修改参数。
4. 保存后即时刷新时薪、分钟价值、秒价值。

验收标准：

- 输入项使用数字键盘。
- 保存后不刷新页面也能即时更新。
- 刷新页面后保留已保存设置。

### 6.2 开始计时

1. 用户选择“带薪拉屎”“带薪吃饭”或“带薪睡觉”。
2. 主计时卡、状态文案和开始按钮同步切换为所选活动。
3. 用户点击开始，主按钮变为该活动对应的结束动作。
4. 首页展示实时计时、实时收益和该活动的随机鼓励文案。
5. 每 250ms 刷新内部计时，每秒级展示给用户。

验收标准：

- 计时过程中主按钮状态明确。
- 三个模式选项的触控区不小于 44px，并可被键盘聚焦。
- 计时过程中锁定模式选项，结束后恢复选择，避免单次记录混入不同活动。
- 计时开始后出现全屏钞票掉落动效，计时结束后停止并清空。
- 收益数字不发生横向抖动。
- 页面切换 Tab 后计时仍继续。

### 6.3 结束并生成战报

1. 用户点击当前活动对应的结束按钮。
2. 系统记录本次活动类型、时长、收益、结束时间。
3. 今日累计次数、时长、收益同步更新。
4. 弹出本次战报。
5. 用户可分享战报或复制文案。

验收标准：

- 本次记录最短按 1 秒计算。
- 关闭战报后数据不丢失。
- 首页“今日累计”顶部只展示当前所选活动的次数、时长和收益，不合并另外两种活动。
- 分模式明细同时展示三种活动各自的次数、时长、收益，并同步标记当前所选模式。
- 不支持系统分享时，自动降级为复制分享文案。

### 6.4 时间账本

1. 用户点击通勤、咖啡、会议、加班等卡片。
2. 页面给出该场景反馈文案。
3. 弹出编辑面板。
4. 用户可修改名称、记录类型、数值、反馈文案。
5. 保存后卡片和时间轨迹同步更新。

四个默认子模块：

- 通勤：记录通勤耗时或交通成本。
- 咖啡/饮品：记录休息时长或饮品支出。
- 会议：记录会议损耗或会议时长。
- 加班：记录加班时长或加班收入。

验收标准：

- 场景名称最多 8 个字。
- 反馈文案最多 80 个字。
- 每个子模块只展示与自身场景匹配的记录类型。
- 数值字段必须随记录类型切换标签、单位、默认值和输入键盘。
- 反馈文案必须随记录类型切换为对应默认文案，保存前可手动修改。
- 用户修改场景名称后，卡片主标题使用新名称；弹窗标题必须是固定大类账单，例如“通勤账单”“饮品账单”，不能跟随“地铁”“自行车”“白水”等具体名称变化。
- 记录方式使用分段选择控件，不使用普通下拉框。
- 刷新页面后保留已编辑内容。

### 6.5 统计

统计页包含：

- 今日次数。
- 累计时长。
- 累计收入。
- 价值换算标签。
- 收益明细。

周期包含：

- 日。
- 周。
- 月。
- 生涯。

验收标准：

- 周、月、生涯在 Demo 阶段可使用模拟基数叠加今日数据。
- 收益明细同步当前周期：日按单次记录、周按星期、月按周次、生涯按年度展示。
- 明细沿用时间轨迹条形样式，每条同时展示次数、时长和收益；切换周期后标签与数据同步更新。
- 迁移小程序后，统计应从本地或云端记录聚合而来。
- 图表或明细不能只靠颜色表达，需要有文字数值。

### 6.6 成就

成就用于长期留存和轻量游戏化。

首批成就：

- 第一泡：完成第一次计时。
- 连续七天：连续七天有记录。
- 累计 100 小时：累计时长达到 100 小时。
- 收益破千：累计收益达到 1000 元。
- 厕所 VIP：本月累计超过 20 小时。
- 马桶战神：单次记录超过 30 分钟。

验收标准：

- 已解锁和未解锁视觉状态明确。
- 解锁条件必须可解释。
- 正式版需要记录首次解锁时间。

## 7. 数据模型

### 7.1 用户工资配置

```json
{
  "salary": 12000,
  "workdays": 22,
  "hours": 8
}
```

字段说明：

- `salary`：月薪。
- `workdays`：每月工作天数。
- `hours`：每天工作小时数。

计算公式：

- 时薪 = 月薪 / 每月工作天数 / 每天工作小时数。
- 每分钟价值 = 时薪 / 60。
- 每秒价值 = 每分钟价值 / 60。

### 7.2 单次计时记录

```json
{
  "id": "session_001",
  "activity": "meal",
  "seconds": 480,
  "money": 18.18,
  "startedAt": "2026-07-28T09:30:00+08:00",
  "endedAt": "2026-07-28T09:38:00+08:00"
}
```

`activity` 可取 `toilet`、`meal`、`nap`，分别表示带薪拉屎、带薪吃饭、带薪睡觉。

### 7.3 时间账本场景

```json
{
  "kind": "commute",
  "title": "通勤",
  "mode": "earn-money",
  "value": 18.2,
  "copy": "通勤也算成本：今天先记一笔路上的精神折旧。"
}
```

记录类型：

- `earn-money`：赚了金额。
- `spend-minutes`：花了分钟。
- `waste-money`：浪费金额。

子模块可用记录类型：

- `commute`：`spend-minutes`、`waste-money`。
- `coffee`：`spend-minutes`、`waste-money`。
- `meeting`：`waste-money`、`spend-minutes`。
- `overtime`：`spend-minutes`、`earn-money`。

### 7.4 分享战报

```json
{
  "title": "时间工资条",
  "sessionSeconds": 480,
  "sessionMoney": 18.18,
  "todaySeconds": 1560,
  "todayMoney": 59.09,
  "shareText": "我刚算了一下今天值多少钱..."
}
```

正式小程序可扩展字段：

- `posterImagePath`：本地生成的分享图路径。
- `shareCode`：用于进入同款战报或小程序首页的短码。

## 8. 视觉和交互规范

整体方向：年轻职场漫画风，像一本会实时计价的打工人漫画。幽默感藏在文案、彩色场景贴纸、漫画网点和收益战报里，不依赖表情包或平台 emoji。

### 8.1 色彩

- 背景：`#eef4f8`、`#f8fbff`，可叠加低透明漫画网点和规则线条。
- 主文字和描边：`#131b2b`。
- 次级文字：`#596377`。
- 主色：`#2f6bff`。
- 成功收益：`#11a66a`。
- 强调色：`#ffdc3f`、`#50d8a5`。
- 提醒和停止状态：`#ff6259`，只用于明确反馈和关键操作。

### 8.2 字体

- Web Demo 使用系统字体栈。
- 微信小程序优先使用系统默认中文字体。
- 数字、金额、计时使用等宽数字特性，避免跳动。

### 8.3 布局

- 手机优先。
- 基准宽度按 375px 到 430px 设计。
- 内容左右边距以 18px 到 20px 为主。
- 卡片圆角控制在 8px，使用粗描边和错位阴影形成漫画层次。
- 底部 Tab 保持首页、统计、成就 3 个入口。
- 固定底栏必须预留安全区。

### 8.4 图标

- 结构性图标统一使用 SVG 或小程序矢量图标。
- 同一层级图标统一 24px、2px 线宽。
- 不使用 emoji 作为导航、设置、关闭、分享等结构性图标。

### 8.5 触控和反馈

- 主要触控区域不低于 44px。
- 点击反馈使用轻微颜色、透明度或缩放变化。
- 动画时长控制在 150ms 到 300ms。
- 支持系统减少动态效果设置。
- 弹窗必须有明确关闭路径。

### 8.6 文案风格

文案可以荒诞，但要克制。方向是“打工人自嘲”，不是低俗堆砌。

可用语气：

- “老板正在为你的肠道健康买单。”
- “你不是在摸鱼，你是在做现金流管理。”
- “会议价值已换算，沉默也有时薪。”

避免语气：

- 过度脏话。
- 攻击具体公司或具体人。
- 让用户产生财务焦虑的严肃口吻。

## 9. 隐私和安全

- 工资配置默认只保存在本地。
- 分享内容不展示月薪、工作天数、每日工时。
- 正式接入云端前，需要明确用户授权和数据用途。
- 任何云端数据同步都要提供退出或清除入口。

## 10. 技术阶段规划

### 当前阶段：H5 Demo

目的：验证信息架构、视觉方向、核心交互。

当前技术：

- `index.html`：结构和页面。
- `styles.css`：年轻职场漫画风视觉样式。
- `app.js`：状态、交互和本地存储。

### 下一阶段：H5 Demo 完善

优先级：

1. 补完整的历史记录列表。
2. 让统计页从真实本地记录聚合，而不是主要依赖模拟基数。
3. 增加战报分享图生成能力。
4. 优化设置和账本表单校验。
5. 增加重置账本和清空数据入口。

### 迁移阶段：微信小程序

优先级：

1. 拆分为小程序页面：首页、统计、成就、设置。
2. 使用 `wx.setStorageSync` 和 `wx.getStorageSync` 替代浏览器 `localStorage`。
3. 使用 `onShareAppMessage` 实现分享。
4. 使用 Canvas 生成战报图片。
5. 根据需要引入云开发处理跨设备同步。

## 12. 验收清单

每次开发完成前需要检查：

- 375px、390px、430px 宽度下无横向滚动。
- 底部 Tab 图标和文字居中。
- 固定底栏不遮挡核心操作。
- 所有主要按钮触控区不低于 44px。
- 计时、金额和统计数字不因变化造成明显布局跳动。
- 所有弹窗有取消或关闭入口。
- 表单保存后有明确反馈。
- 分享不可用时有降级方案。
- 结构性图标不使用 emoji。
- 新增文案符合“荒诞但克制”的调性。

## 13. 待决策问题

- 名称已确定为《时间工资条》，若微信审核要求行业资质，再启用不含“工资”的备选名称。
- 真实排行是否接入微信好友关系，还是只做匿名榜单。
- 战报分享图是否要包含二维码。
- 是否支持多份工资配置，例如主业、副业、自由职业。
- 是否支持跨设备同步。如果支持，需要明确登录、云端存储和删除策略。
